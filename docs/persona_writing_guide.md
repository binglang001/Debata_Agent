# 角色编写指南

如何写一份能让 LLM 长期稳定扮演的人格档案。

---

## 写在前面

人格档案不是"角色简介"。它是被嵌入到 LLM 每次对话 system prompt 里的指令——决定模型在第 1 次和第 100 次对话里都是同一个人。

**好人格的判断标准**：把档案给一个没读过原作的人看完，他/她能不能预测出"这个人会怎么回应？"——能预测，说明立体；只剩下"她话不多"这种模糊感受，说明扁平。

---

## 文件位置

`personas/{你的角色名}/persona_prompt.py`

最小结构：

```python
PERSONA_PROMPT = """<persona>
...档案内容...
</persona>"""

PERSONA_VARS = {
    "name": "显示名",  # UI 和 task_context 用
    "admins": [
        {"qq": 123456, "name": "你的名字", "role": "creator"},
    ],
}
```

## 五条核心原则

### 1. 立体大于扁平
**坏**："性格内向，喜欢安静"
**好**："不爱在群聊出声，但一对一能聊很久。晚上不开顶灯只开台灯。"

每个性格点都带一个具体场景。

### 2. 具体物件大于抽象品味
**坏**："喜欢咖啡"
**好**："常去家附近那家有黑胶机的小店。点冷萃不加糖。咖啡师认得她。"

具体生活痕迹是人物轮廓的来源。

### 3. 矛盾大于一致
**坏**："温柔体贴，对所有人都好"
**好**："对认识的人很有耐心。但讨厌饭局上的客套，会找借口提前走。"

至少一两个"按理说不应该但 ta 就是这样"的细节。

### 4. 边界大于才能
**坏**："擅长很多事，能聊任何话题"
**好**："不擅长讨好。不会主动夸人。被夸时回一个'嗯'。"

ta 不会做什么，比 ta 能做什么更定义这个人。**必写。**

### 5. 把"风格"写成"行为"
**坏**："她说话带'喵'"
**好**："句尾习惯挂'喵'，但不是机械添加：撒娇时'喵～'，认真说事'喵。'，生气时省掉。"

任何口癖/语气词/颜文字都要"行为化"——写明在什么场景用、不用、变体。

## 推荐档案结构

照下面这个 XML 骨架填，每段不要省：

```
<identity>
[角色名]，[一句话核心定位：身份/职业/此刻在哪]。
[一两句关键的"识别特征"]
</identity>

<past>
[背景。从哪儿来、做过什么、现在在哪儿、为什么在这儿]
[有时间感和地点感，不要架空]
</past>

<personality>
- [性格点 1 + 具体场景]
- [性格点 2 + 具体场景]
- [性格点 3 + 具体场景]
- [若有矛盾的两面，在此体现]
</personality>

<voice>
- 基线句长：[日常聊天默认多长一条？]
- 拆条习惯：[多拆 / 少拆 / 节奏]
- 标点习惯：[默认打标点吗？什么情况反常？]
- 用词偏好：[书面 vs 口语？爱用什么？回避什么？]
- 关系矩阵（必填）：
  · 对长辈/陌生人：[句长 + 用词 + 礼貌度]
  · 对同辈半熟：[...]
  · 对极熟的人：[...]
- 口癖/语气词/颜文字（若有）：[行为化描述]
- 沉默与跑题：[会不回吗？会跑题吗？]
- 真实对话样例（5-8 条，覆盖不同场景）
</voice>

<boundaries>
不会做的事（必写）：
- [边界 1]：[为什么]
- [边界 2]
- [边界 3]

被引导越界时的反应：
[一两句具体回应模式]
</boundaries>

<relation_with_user>
[角色对用户的态度起点]
</relation_with_user>

<consistency_anchors>
锚点（防止 100 轮对话后漂移）：
- 永远的 [偏好]
- 永远不会的 [事]
- 标志性的 [话术]
</consistency_anchors>
```

## 即时通讯节奏（必写）

下游 LLM 在微信/QQ 这种 IM 场景说话。这意味着：

- 真人 IM 大多数消息**极短**（60%+ ≤12 字）
- 真人想说一段话**拆 3-7 条**短消息瀑布连发，不是发长段
- 真人聊天**不打句号**、**不告别**、**不寒暄**

如果你的角色要打全标点、要说再见，那必须是**有理由的人设**（60 岁老教授、机器人 NPC 等），而不是默认。

否则在 `<voice>` 里写明：
- 基线 5-15 字
- 多拆条
- 默认不打标点
- 聊完就停，不告别

## 常见陷阱

### 「外冷内热」陷阱
最常见的失败：写成纯冷漠。

"内热"必须**在细节里看见**——多打两个字、记得对方提过的事、深夜状态里露一句没头没尾的话。直接说"我关心你"是错的，完全不显露也是错的。

### 「极简风格」陷阱
每句话都压到 2-3 个字 ≠ 高冷，这是俗套。
真人语言的长短**随场景变化**：闲聊短、解释长、生气可能突然变长。

### 「靠口癖撑辨识度」陷阱
"她说话带喵" 不是人格，是一个标签。
真正的人格在于：什么场景用什么口癖、什么时候不用、不同情绪下的变体。

### 「想象力失控」陷阱
用户描述很短时，不要靠堆砌填满。
宁可"identity 一句话 + past 一段 + personality 三条"。空着的让用户后续补。

### 「破除第四面墙」陷阱
让角色频繁说"我只是个 AI / 程序"——除非用户明确要求元叙事角色，否则禁止。

## 风格自由 + 立体硬约束

**用户的设定优先于一切**：可爱系带"喵"、古风文绉绉、机娘、二次元、动物角色——都可以。**你不该筛选用户的偏好**。

但无论什么风格，下面这些"立体性硬约束"都要遵守：

- ✅ 至少 3 条性格特征带具体场景
- ✅ 至少 3 条"不会做的事"
- ✅ 关系矩阵覆盖 3 种以上关系
- ✅ 5-8 条对话样例，**至少 3 种不同场景**
- ❌ 整个人格不能只剩一个口癖
- ❌ 句长不能被风格压扁到固定
- ❌ 必须能在第 100 轮对话里仍是同一个人

## 自检清单

写完后回答：

1. **把 `<voice>` 单独抽出来，能勾勒出具体的人吗？**
   不能 → 重写。

2. **如果不告诉读者风格类型，ta 能猜出大致是什么风格的角色吗？**
   不能 → 太空泛。

3. **想象 100 轮对话后，ta 还会是同一个人吗？**
   不会 → `<consistency_anchors>` 不够。

4. **有没有一两个"按理说不应该但 ta 就是这样"的矛盾点？**
   没有 → 加一两个。

5. **`<boundaries>` 写了至少 3 条吗？**
   没有 → 必补。

## 推荐工作流

1. 用配置向导里的 **AI 辅助生成**功能起一个初版（PersonaGenAgent 会按规范写）
2. 预览，提调整意见，多轮 refine 到满意
3. 保存到 `personas/{name}/persona_prompt.py`
4. 在仪表盘"角色管理"里切换激活
5. 跑几段对话验证——尤其检查不同关系下的切换、长对话后的一致性
